# Studio 使用流程排查 — 2026-09-29

基于 `eaa3f51` 加现有 PI/Codex、聚合 Decode 和界面改动进行检查。
本轮修复集中在模型选择、启动反馈及运行中 Agent 的模型保护。

## 已复现并修复

| 场景 | 原来的问题 | 修复后的行为 |
| --- | --- | --- |
| 聊天模型未启用工具调用，转到 Agent | 同一个模型被标记为“使用中”，无法选择支持工具调用的预设 | 根据实际运行预设和能力判断，可启动该模型的 Agent 预设 |
| 在选择器中切换模型，保持弹窗打开 | 启动完成后，旧模型仍显示“使用中” | 随模型状态刷新选项，用当前预设判断使用状态 |
| 启动进度接口暂时不可用 | 错误被忽略，继续显示排队或旧进度 | 明确显示正在恢复状态，恢复后显示实际结果 |
| 状态查询失败 | 页头、服务页仍显示就绪，聊天仍允许提交 | 显示连接中断，暂时禁用新消息提交，保留草稿并自动恢复 |
| 状态请求一直没有响应 | 轮询被永久卡住，旧状态一直显示 | 实时轮询 15 秒超时后继续恢复；慢速目录查询、上传、提交操作不套用此限制 |
| Agent 正在执行工具或收尾时，从预设页启动或重试模型 | 这些入口绕过了模型选择器的 Agent 保护 | 模型启动队列统一拒绝启动，任务完成或停止后才允许继续 |
