# Studio 第二轮使用流程排查 — 2026-09-29

接续第一轮模型就绪与状态同步修复，重点检查聊天停止、后台收尾，以及
Agent 与模型切换之间的并发冲突。以下问题均先通过失败用例复现，再修复验证。

## 修复内容

| 场景 | 修复前 | 修复后 |
| --- | --- | --- |
| 新对话等待首个 token 时停止 | 页面尚无会话 ID，只结束前端等待，后台继续生成 | 停止绑定实际提交的生成任务；提交响应延迟时等待任务 ID，保留草稿 |
| 停止接口返回错误或一直不返回 | 出错后停止按钮消失；等待响应时按钮可能永久禁用 | 失败后可重试；15 秒未确认则提示结果未知，继续同步后台状态 |
| 停止请求发出后切到另一段对话 | 旧响应晚到会解除新对话的生成状态 | 停止结果只更新原操作所属的页面状态 |
| 旧页面的停止请求晚于新一轮生成 | 按会话停止，会误取消该会话的新一轮 | 前端附带 `run_id`，后端忽略过期任务的取消；旧 API 无参数请求仍兼容 |
| 多次停止、停止期间服务关闭或 HTTP 请求断开 | 重复取消打断上游连接清理 | 只发出一次任务取消，并保护收尾等待，保留部分回复 |
| 连接关闭异常、协程启动前被取消 | 持久记录停留在生成中，或者最终回复没有保存 | 关闭异常不阻断回复落盘；协程完成回调兜底结束状态 |
| Agent 执行工具期间卸载模型或加载同卡创作模型 | 没有进行中的推理请求时，仍可卸载 Agent 依赖的模型 | 提交阶段和后台执行阶段都检查尚未结束的 Agent；保留强制卸载入口 |
| 模型切换已排队，随后启动 Agent | Agent 绑定即将卸载的旧模型 | Agent 创建与模型切换共用文件锁；排队中的切换明确拒绝新任务，不影响其他 GPU 的创作模型 |

普通页面离开或刷新仍只断开订阅，后台聊天继续生成。停止失败时不自动重新
发送聊天请求；用户可重试针对同一个 `run_id` 的停止操作。
