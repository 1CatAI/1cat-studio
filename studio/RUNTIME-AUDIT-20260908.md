# 环境安装审计 · 2026-09-08

本轮覆盖 GitHub Releases 环境安装的失败恢复、文件校验、重复操作、任务同步和界面反馈。以下问题均有修复前复现及修复后回归，不调整主机 GPU，不启动或停止模型。

| 问题 | 修复行为 | 验证 |
| --- | --- | --- |
| 安装失败后，已有虚拟环境导致每次重试再次失败 | 重试保留未注册环境和已安装依赖，继续安装；已登记环境保护保持有效 | 实际离线 uv 环境重建，确认依赖标记文件保留 |
| 发布说明修改后，同一 wheel 再次提交产生重复任务 | 按不可变发行附件标识合并正在进行的安装 | 修改标题、PyTorch 展示信息后重复提交，只返回原任务 |
| 连续取消会重复中断工作进程，可能打断子进程清理 | 取消操作幂等，只发送一次中断信号 | 同任务连续取消，信号计数为一 |
| 已完整下载、尚未改名的临时文件会重新下载 | 先验证临时文件 SHA256，完整文件直接恢复 | 禁止网络请求仍能正确恢复 |
| 服务器返回错误续传范围时，有效临时文件被追加污染后删除 | 写入前校验 Content-Range，拒绝错误范围并保留原分片；不完整传输可继续重试 | 错误范围、正确续传、服务器忽略 Range、截断传输 |
| 已读取的官方哈希信息互相冲突时未明确拒绝 | API digest 与校验文件不一致则禁用对应发行包 | 两个哈希来源冲突，配套 wheel 有完整校验信息 |
| 某个版本校验文件读取失败导致整个发布目录刷新失败 | 错误限定在对应版本，其他正常版本仍可安装 | 混合正常与失败发行包，正常条目继续可用 |
| 直接安装默认版本后，新版本出现会改变当前选择 | 开始安装即持久保存当前版本，后续列表更新保持选择 | 浏览器安装后插入新发布，安装目标与选择保持一致 |
| 旧失败任务更新后遮住新的重试进度 | 优先显示运行中的任务，结束记录按创建时间排序 | 旧失败记录晚于新任务更新，仍显示新任务进度与取消入口 |
| 切换发行版本后仍显示上个版本的成功图标 | 操作反馈按发行版本隔离，切换立即重置 | 成功状态期间切换另一版本，不残留对勾 |

验证包括 77 项针对性后端测试、6 项前端单元测试、TypeScript 检查、生产构建，以及 7 组浏览器回归。浏览器覆盖中英文、深浅主题、移动端、键盘、减少动态效果、快速切换、跨页恢复、失败重试及离线缓存。

回归使用临时数据库、模拟 HTTP/安装任务和软件渲染；真实 uv 测试只创建临时 Python 虚拟环境，不安装推理包。没有执行 GPU 模型推理，因此这些结果不代表所有发行版本已通过实际模型验收。

复现与测试入口：`backend/onecat_tests/test_runtime_audit.py`、`backend/onecat_tests/test_runtime_releases.py`、`scripts/check-runtime-audit.py`、`scripts/check-runtime-releases.py`。具体日志、部署备份和读回结果存放在工作区 `.artifacts/runtime-audit/`。
