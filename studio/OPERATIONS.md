# 1Cat Studio 运行手册

## 安装与访问

解压管理器发行包，运行 `bash scripts/install.sh`。默认程序目录为 `~/.local/share/onecat-studio-app`，数据目录为 `~/.local/share/onecat-studio`。安装器支持 `--prefix`、`--state-dir`、`--no-service`，无需安装 CUDA、Node 或系统 Python。需 Linux x86_64 / glibc；GPU 驱动由主机提供。

默认只监听 127.0.0.1:8888。远端使用 `ssh -L 8888:127.0.0.1:8888 -p PORT USER@HOST`，然后打开本机浏览器。首次管理员初始化只接受本机连接或 SSH 转发。设置页可更改端口、开启局域网访问；保存并重启 Studio 后生效。服务页的 API 标签会显示当前活动网卡的局域网接入地址，不把 IP 固定在安装包里。同一局域网的客户端使用该地址和 API Key；局域网外使用 SSH 转发或 HTTPS 反向代理。

0.3.1 起，GPU 控制助手随管理器默认安装，自动检测 GPU UUID，无需另行下载。
安装器在管理员授权后写入受限控制程序及规则；升级保留原有 GPU 权限限制，
不会自动改变功率、时钟或扩大已授权的显卡范围。
终端安装可通过 sudo 授权；桌面安装使用系统授权窗口。无交互权限时，Studio
仍可使用，设置与安装引导页会提供“启用 GPU 控制”入口。这个入口在服务器桌面
发起授权，密码由系统处理，网页不接收密码；无桌面的服务器需管理员在安装时授权。
取消或失败可重试，授权成功后自动确认可控制卡数。保留旧安装脚本兼容性，
其 GPU UUID 参数现已可省略。

```bash
systemctl --user status onecat-studio.service
systemctl --user restart onecat-studio.service
journalctl --user -u onecat-studio.service -n 100
```

安装器默认启用 Studio 用户服务。设置页显示用户服务与 linger 状态；需要无人登录也自启时，由管理员执行 `loginctl enable-linger USER`。安装器不会更改系统显卡驱动。

## 推理环境与模型

安装引导支持四条路径：

1. 选择安装 1Cat-vLLM 1.5.0 或 1.3.0 SM70 wheel，校验 SHA256；使用独立 Python 3.12、Torch 2.10 / CUDA 12.8 环境。首次至少预留 20 GiB，不包含模型。
2. 导入现有 Python 环境，可指定工作目录与环境变量；导入会实际验证 torch/vllm，记录源文件指纹。
3. 导入 Studio 导出的离线运行包。只有包含自身 Python 的受管理环境可导出；外部 Conda/source 环境应在目标机器按原始方法准备后导入。
4. 接管正在运行的 1Cat systemd 用户服务。读取真实 argv、环境、GPU UUID 与 API，不重复加载权重。PR417 DFlash2 配置另外生成一个关闭推测解码的基础预设。

接管后第一次停止旧服务时，会禁用旧单元的开机自启并记录其原状态，避免它与 Studio 的自启预设竞争显存。恢复原部署可先在 Studio 停止模型，再执行 `systemctl --user enable --now ORIGINAL.service`。旧服务脚本和模型文件保留不变。

模型库可导入 safetensors/PyTorch 模型目录，也可搜索版本化的已验证 ModelScope 目录。默认只显示匹配本机硬件及所选环境的检查点；“全部已验证”显示其他配置的要求。下载接口同样校验目录、版本、GPU 和固定文件清单，不接受任意仓库或 GGUF-only 权重。下载任务固定 revision 的 SHA256 文件清单，并在完成后逐文件校验，失败/取消后可从服务页重试续传。受限模型在设置中填写 ModelScope token。不同量化/架构的兼容性取决于实际导入的运行环境；启动失败会保留真实日志。

启动预设保存 GPU UUID、TP、dtype、量化、KV、上下文、batch、graph、attention、推测解码和额外 argv。单个 GPU 同时被其他计算进程占用时拒绝启动。新模型在单独 systemd 用户单元中运行；无用户 systemd 的开发环境使用独立进程组。Studio 重启不会主动终止正在运行的模型。在模型库的启动预设卡片或设置页可以选择唯一一个开机加载预设；取消选择则只启动 Studio。要让模型在无人登录时开机加载，需要 Studio 用户服务和 linger 均已启用，且未设置 `ONECAT_AUTO_GPU_ACTIONS=0`。空闲卸载也在设置页配置。

## 聊天与 API

聊天记录复用上游 SQLite 存储。支持编辑重发、重新生成、停止生成、系统提示词、采样、思考开关与 JSON 导入导出。生成中定期保存收到的内容；关闭页面会取消该浏览器请求。浏览器突然崩溃时最多丢失最近一次持久化之后的内容。

`/v1/models`、`/v1/chat/completions`、`/v1/completions` 使用服务页生成的 Bearer API Key。API Key 无管理权限，完整密钥只显示一次。SSE 数据块数量不作为 token 数量；指标来自上游 usage / token IDs。聊天与服务页共用请求指标。优先使用单请求可隔离的 vLLM prefill/decode 指标，校验完成数和输入输出 token 数；有并发或无法隔离时，Decode 使用服务器本机 token IDs 到达时间，扣除整个首批 tokens。Prefill 扣除缓存命中的 tokens，缓存信息不全时不显示该速率。缺失计时不冒充 E2E 或纯 decode。TTFT 与完整请求耗时分开显示，浏览器网络和保存消息的耗时不参与 Decode。

## 功率与能效

实时及曲线功率单位均为 W，范围是所选 GPU 板卡，不包括 CPU、内存、电源损耗。Wh/请求保留在能量明细中。最低 W 不一定有最低单次请求能量。

三个 V100 快捷档位：省电使用 975 MHz 锁频、150 W/卡硬件上限，参考此前测量目标约 110–120 W/卡，实际值随模型、上下文和 DFlash2 状态变化；均衡使用 185 W/卡上限和动态频率；性能使用 300 W/卡上限和动态频率。V100-SXM2 的驱动最低功率上限为 150 W，不能把 120 W 当作可设置的上限。0.4.0 起，功耗控制独立于模型，默认作用于整机已授权 GPU，也可自选。仅与 Studio 当前请求用卡重叠时等待请求结束；外部程序占用不阻止显式调节，调节不停止外部进程。成功后按 GPU UUID 保存完整策略，启动模型不会再应用旧预设的 hardware_profile。

后台统一每 0.5 秒从 NVML 采样，与页面打开状态无关。页面每秒刷新采样时间、总功率、每卡功率和显存，以及最近两分钟曲线。超过三秒未更新标为暂停，数值显示为空；功率上限与瞬时读数分开显示。显存为物理分配量，包含引擎预留的 KV 缓存，不等于已使用的 token 容量。

服务页保留最近 200 条请求，显示纯 prefill/decode（注明来源）、TTFT、token 数、请求期间平均 GPU 功率和耗电估算。耗电按 0.5 秒功率采样对请求时间窗积分；采样缺失不补造数值。并发期间是这些 GPU 的同期总量，不拆分成单请求独占耗电。旧记录没有新增计量数据时保持为空。

控制助手随安装器自动配置。旧部署可在设置页点击“启用 GPU 控制”补齐授权；
无桌面环境也可由管理员运行兼容脚本，它会自动识别本机显卡：

```bash
bash scripts/install-gpu-helper.sh
```

助手 root 所有，只允许当前用户操作列出的 GPU，校验驱动支持的功率/时钟范围。已有允许列表不自动覆盖。首次直接选择档位即可，助手会在同一事务内建立动态时钟基线。策略账本绑定主机 boot ID，重启后不会相信旧锁频记录。全部设备预检查成功后写入，失败按逐卡快照恢复；原锁频未知时只能恢复原功率上限与动态频率，界面会明确标注。不要用其他工具同时修改锁频；驱动无法反查这类外部修改，必要时用动态频率重新建立基线。NVIDIA 接口无法可靠读取既有 GPU locked-clock 策略，不能把采样到的时钟当成锁频设置。

一键校准默认 8192 输入 / 1024 输出、单请求、greedy seed=42、关闭 thinking 和 DFlash2/MTP。每个档位预热一次并测三次，唯一 cache_salt 排除 prefix hit。Prefill 和 decode 均来自隔离请求的服务端指标，token 到达时间另外保留用于对照。采集器按 200ms 间隔检查取消，避免逐 token 数据库操作干扰测量。每次检查输入输出长度、输出 token 一致性与基本健康状态；这不替代模型通用质量评测。

默认比较动态频率和 900/930/975/1020 MHz（限驱动支持），不自动应用推荐。推荐在用户设置的最低 prefill、decode、最高 TTFT 约束下选择请求能量最低的有效档位；能量落在测量波动范围内时优先更快的档位。运行中/失败/硬件未恢复或配置不匹配的结果不能推荐。

校准结束、失败或取消时恢复此前的功率/锁频。SIGKILL 留下恢复日志，Studio 重启时尝试恢复；失败会显示恢复错误并阻止新的模型启动和校准。原始 prompt token、响应 token、到达时间、功率采样、指标差值和恢复日志位于数据目录 `benchmarks/RUN_ID`。历史 V100 8K/1K 曲线仅作为参考，不能直接当成当前模型的验证结果。

## 备份、升级与回退

设置页创建/下载会话和配置备份，不含权重。备份包含凭据，按私密数据保存。恢复要求模型与后台任务停止，会替换数据库并撤销浏览器登录。服务器路径导入适合大文件，避免浏览器重复上传。

升级管理器：结束正在进行的请求和任务，解压新包，再运行相同参数的 `scripts/install.sh`。安装器保留旧 release，备份数据库，原子切换 `current`。推理环境升级通过导入新环境并修改预设完成，旧环境保留。

管理器回退前停止模型与任务：

```bash
python3 ~/.local/share/onecat-studio-app/current/scripts/rollback.py
```

回退会恢复上次升级前的数据库；升级之后新增的会话先另行备份。自定义安装目录作为 rollback.py 的第一个参数传入。

## Studio 0.2：启动恢复与预设

启动阶段由后台持久保存，浏览器全局共享查询（启动中每秒、平时每两秒；焦点、网络恢复和导航立即同步）。只有本次启动的进程身份、健康接口和模型名称检查通过才就绪。加载阶段仅展示日志中的分片/Graph 真实计数；无计数时不显示百分比。长时间编译保持进行中；进程退出、失败、取消及后台任务失效均有恢复入口。切换页面不取消模型启动。

新建预设默认 FP16、加速关闭、输出长度自动。V100 的 BF16 在保存和启动时均被拒绝，auto 计算精度转为 half。工具、视觉、MTP、DFlash2 依据具体检查点与环境的能力记录开放。高级 JSON 保留。DFlash2 使用本地草稿目录，并强制 Hugging Face 离线模式；新增草稿从 ModelScope 下载。

升级迁移将旧版固定 1024 的聊天/预设默认值改为 null（自动），其他手动值保留；迁移前备份两份 SQLite 数据库。自动模式省略请求中的 max_tokens，由 vLLM 的 generation_config 和实际 token 化后的剩余上下文决定。基准测试的输出长度不迁移。

聊天设置新增 `max_tokens_mode=auto/manual`。未携带模式的旧页面默认 1024 会在保存和 Studio 请求入口归一化为自动，避免升级后再次写回；明确标记 manual 的 1024 和其他自定义上限仍生效。OpenAI `/v1` API 不作此兼容转换。达到长度上限的回答显示提示，并可使用自动长度重新生成。

版本化目录位于 `backend/onecat/data/verified-models-v1.json`，包含证据、固定文件 SHA256、GPU 拓扑、版本要求和配方。首轮已核对 QUASAR Qwen3.8-27B NVFP4 与 GLM-5.3-Flash NVFP4 的 ModelScope 文件清单及项目证据；GLM 的 TP4/PP2 配置仅在“全部已验证”显示要求，不提供一键下载启动。Qwen3.6 本地混合量化、Flash-Next、GLM、DeepSeek 和多模态组件的审计原因可在目录底部查看；没有证据的检查点不自动获得已验证标签。原有本地模型继续保留。

## 图片、流式动画及网页预览

图片聊天由已启用且通过验证的视觉预设开放，支持上传、粘贴、缩略图和移除；PNG/JPEG/WebP 每张最多 10 MiB，最多四张，并服从模型更严格限制。本机当前 PR417 预设实际验证为每条一张。附件在私有目录持久化，读取需要管理员登录；聊天 JSON 导出携带图片数据及关联，备份包含附件目录。Studio 不执行工具调用；API 客户端自行处理工具协议。

聊天指标优先使用能隔离到本次请求的服务端统计，缓存、并发、延迟刷新污染不能排除时不展示 Prefill。Decode 的本机流观测值明确标记来源。取消或中断不生成速率；单 token 无 decode 时间区间时显示缺失原因。动画不进入计时。

默认新增文字采用 280 ms 模糊渐显，延迟上限 70 ms，已显示文字不重复动画；组合 Emoji 保持同一字形。对话参数可关闭动画，系统减少动态效果设置优先。

代码块的“预览 / 运行”支持 HTML/CSS/JS、SVG、单文件 JSX/TSX。点击后约每 500 ms 更新可解析版本，错误时保留上次成功画面。React、ReactDOM、Lucide、Recharts、Tailwind 内置；不下载未知 npm 依赖。编译和执行都在无同源权限的浏览器 iframe 沙箱中，外网资源、fetch、子 iframe、表单及父窗口访问受限制。预览不会在服务器运行生成代码。可查看源码、错误、重跑、暂停更新、全屏及下载；关闭或切换会话即释放实例。

预览默认在聊天页右侧占一半宽度，可拖动至 30%–65%；窄屏为页内上下分栏，保留输入框。只有主动点击全屏按钮才覆盖页面。预览模块和 Markdown 代码块有独立错误边界，模块加载或渲染失败不会卸载聊天。HTML 页面禁止缓存以减少旧前端残留。

预览内的 localStorage/sessionStorage 是独立的内存存储，可供小游戏保存本次分数；不会读取 Studio 存储，关闭或重新运行后清空。重新生成当前回答时，已打开的预览跟随新回答更新。

长思考内容折叠时不执行 Markdown 渲染；展开后，新文字仍使用 280 ms 模糊渐显，已显示文字退出动画层。生成状态固定在消息标题处。向上滚动查看内容会暂停跟随，点击“回到最新”恢复。渲染更新合并不改变保存文本或后端速度统计。生成结束不会自动打开预览；已因页面崩溃中断的旧回复需要重新生成。

验证命令：后端 `.venv/bin/pytest -q studio/backend/onecat_tests`；前端 `npm --prefix studio/frontend run build:onecat`；浏览器 `python studio/scripts/check-browser.py`（该 Python 需安装 Playwright/Chromium）。浏览器检查使用临时数据库及模拟 GPU 清单，不启动或调整真实 GPU。


## 0.4.0：动效和独立 GPU 策略

状态切换统一为 200 ms，紧凑控件 160 ms，预览面板 220 ms；设置里的「界面动效」独立于 280 ms「柔和流式动画」。系统减少动态效果优先，运行中改变系统偏好也立即生效。后台轮询不重新播放页面或消息入场；只有导航、展开、阶段变化、附件增删等操作触发动效。

`GET /api/gpu/power-modes` 返回全部设备、授权和占用、已确认策略与任务；重复 `gpu_uuids` 查询参数可限定范围。`POST /api/gpu/power-mode` 接受 `{id,gpu_uuids}`，`POST /api/gpu/settings` 接受 `{setting,gpu_uuids}`。新接口未指定范围时选全部已授权 GPU；旧 `/api/inference/power-mode`、`/api/inference/hardware` 保留预设 GPU 范围。提交后 UUID 固定，切换模型或页面选卡不改变排队任务。

启动、停止、校准与硬件任务共享跨进程操作锁。相同范围和设置的并发提交合并为一个任务；其他设置在当前任务结束或取消后再提交。等待可以取消，硬件写入期间显示应用中，结束后再根据助手确认结果显示已应用。Root 助手使用事务日志，崩溃或恢复失败保留待恢复设备，后续恢复任务先完成恢复，不把部分恢复显示为成功。

升级备份 SQLite 数据（含每卡策略）及 GPU 控制配置、锁频账本和待恢复日志。新版助手为旧 Studio 保留原 snapshot 协议，可直接回退旧安装。恢复已保存策略通过同一任务队列执行，只改不一致设备；校准仍保留原独占检查和临时设置，最后恢复进入校准前的策略，不修改用户已保存选择。

`studio/scripts/check-motion-power.py` 验证模拟八卡、独立选卡、范围切换竞态、排队取消、手动校验、混合配置、界面动效开关、系统偏好动态变化、预览实例存续、复制位置、展开和移动端。使用临时数据库与假的 GPU 控制器，不会写入主机 GPU。


### 更新服务时不自动操作 GPU

在 systemd 用户服务的 drop-in 中设置 `Environment=ONECAT_AUTO_GPU_ACTIONS=0`，并在执行安装器时传入同名环境变量，可以更新界面、管理服务和内置助手而不自动恢复功耗策略、恢复未完成的硬件操作、接管模型、自启模型或空闲卸载。监控仍只读采样。显式点击启动、停止或应用功耗档位仍按用户操作执行；此开关不替代管理员授权策略。解除暂停时移除对应 drop-in 后重新加载、重启管理服务；恢复操作会在下次启动通过队列核对执行。

## GitHub Releases 推理环境安装

安装引导的“自动安装”从 `1CatAI/1Cat-vLLM` 的 GitHub Releases 读取 wheel，按发行版本选择；“检查更新”刷新列表，默认隐藏实验版。GitHub 的 prerelease 标记和发布标题中的 Beta/Experimental 都会识别。发布目录缓存 15 分钟；网络失败保留上次列表并明确提示，首次离线提供原有 1.5.0/1.3.0 校验和固定的备用项。

遇到 GitHub API 限流时，目录读取会尝试复用运行 Studio 的系统用户已有的 `gh` 登录；调用限定为本项目公开 Releases 的只读 API，不弹出登录窗口。部署者也可在服务环境设置 `ONECAT_GITHUB_TOKEN`，仅用于 GitHub API 请求头，凭据不返回前端、不写入发布目录、不传给 wheel 下载地址。未配置登录仍可匿名读取；失败时继续使用缓存并提示原因。

`GET /api/runtimes/releases` 返回来源、更新时间、逐项可用性、已安装环境及配套文件；`?refresh=true` 手动刷新。`POST /api/runtimes/install` 只接受目录中的 `release_id`，服务端固定任务的 GitHub 附件、哈希及配套 wheel，忽略客户端提供的安装地址。旧版 `1cat-vllm-1.5.0` / `1cat-vllm-1.3.0` 标识仍兼容。现有 `/api/runtimes` 的 releases 字段返回已缓存目录，查询环境列表本身不触发外网访问。

每个安装使用独立前缀，按附件身份与全部 SHA256 区分；不同版本或重新发布的附件不会覆盖已有环境，不自动修改启动预设、不重启模型。相同任务合并、同一前缀的工作进程串行执行。界面原位显示真实下载字节、速率、安装阶段、取消与重试；完成后需要在模型预设中显式选择新环境。

安装先校验原始 GitHub wheel 的 SHA256，再读取 METADATA 确认 Python、精确 PyTorch/torchvision/torchaudio 版本及 CUDA 构建；支持精确版本依赖及 PyTorch 官方的直接 wheel URL。旧发布的 FlashAttention 配套 wheel 与 vLLM 一起安装。对于文件名版本与 METADATA 不一致的历史 wheel，在校验原包后只规范本地安装文件名，不修改文件内容；发行版本和包内版本分别保存在环境记录中。缺少校验和、兼容平台或明确 CUDA 目标的发行包不可自动安装，未知 Torch ABI 依赖在安装 PyTorch 前拒绝。

环境验证确认可导入及实际 Torch/CUDA 版本匹配，不等同于每个模型已经通过推理或性能验收。新增发布不会自动获得模型目录中的验证标签。Miniconda 安装与通用 Conda 环境管理不属于此功能。

### 安装恢复与界面状态回归

失败后重试保留尚未注册的虚拟环境及已安装依赖，继续安装；已登记的环境仍禁止覆盖。同一发行附件的任务按不可变发行包标识合并，发布说明修改不重复创建任务。取消请求只发送一次中断信号，重复点击不会打断工作进程对子进程的清理。

完整的临时下载文件先校验 SHA256，可直接恢复为完成文件。续传严格核对 HTTP Content-Range，错误范围不改写已保存分片；未传完整的文件保留供重试，完成进度回填实际字节数。单个发行版的校验文件异常仅禁用对应发行包，其他版本仍可选择；已读取的 SHA256 来源冲突会阻止安装。

开始安装会固定当前版本选择，之后列表更新不自动切到其他版本。同版本存在多次任务时优先展示正在执行的任务，再按创建时间选择最近记录，避免旧失败记录遮住重试进度；切换版本清除原操作按钮的成功或失败反馈。

针对性回归：`backend/onecat_tests/test_runtime_audit.py` 含实际离线 uv 虚拟环境恢复及模拟 HTTP/进程测试；`scripts/check-runtime-audit.py` 在临时数据库和模拟安装器上覆盖新版本出现、连续切换和旧任务延迟更新。浏览器使用软件渲染，不执行模型或 GPU 设置。
